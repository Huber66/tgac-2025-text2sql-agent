# 项目导览

从业务问题、上下文构造到 SQL 执行与结果保存，本页介绍主要模块及示例运行顺序。

## 项目概述

这个项目把游戏数据分析问题转成 StarRocks SQL。难点除了生成合法语法，还包括确定统计人群、时间口径和跨表关联。实现中先按题目表列表构造上下文，再注入业务知识和逐题逻辑指引。LangGraph 管理工具调用与提交过程，执行错误交回 Agent 修正，已知错误结果由拦截器识别，最终 SQL 会重新查询数据库后保存。

公开仓库附独立自造数据，既可以执行已有 SQL 验证环境，也可以让模型重新解题；还提供固定工具序列的闭环回放，帮助观察拦截器的实际行为。

## 阅读与运行顺序

1. 在[方案设计](solution.md)说明有限参考样本和业务口径问题，再打开[架构说明](architecture.md)定位实现。
2. 执行 `python main.py --cache_only` 与 `python scripts/verify_demo.py`，确认数据库和输出格式。
3. 执行 `python scripts/replay_demo.py`，展示空结果被拦截、修正规划和最终重执行。明确这一步使用预设工具调用。
4. 有可用 API 配置时，再运行 `--ignore_cache --rerun_ids sql_1`，展示真实模型工具调用。

## 主要实现入口

| 处理环节 | 代码入口 | 内容 |
| --- | --- | --- |
| 读取任务与启动执行 | `main.py` | 题目选择、缓存控制与任务调度 |
| 构造上下文 | `prompt_engine.py` | 表结构、业务知识与逐题逻辑指引 |
| 查询与格式化 | `execution_tools.py` | StarRocks 连接、SQL 执行和数值处理 |
| 提交反馈 | `main.py` 中的拦截器 | 错误结果比较、限次重试与最终提交 |
| 维护答案与知识 | `manage_answers.py`、`generate_logic_guide.py` | 答案录入、错误样本与逻辑指引提炼 |

## 三种运行方式

- **缓存执行**：使用 `--cache_only`，重新执行答案库中的 SQL，并保存当前查询结果。
- **固定序列回放**：运行 `scripts/replay_demo.py`，通过预设工具调用观察拦截、修正规划和最终重执行。
- **模型生成**：使用 `--ignore_cache`，让模型结合上下文与执行反馈生成查询。

## 结果与知识维护

逐题执行记录保存在 `output/<profile>/api_langgraph_runs/`，结果按题目 ID 更新到 JSON 文件。根据外部评测或人工复核结论，可以录入正确答案和错误样本，再维护对应的 Logic Guide，供后续运行使用。
