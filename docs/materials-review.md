# 原始资料与公开实现的核对

本次补充使用了项目提供的两份历史资料：两页的《腾讯 TGAC 算法大赛 PPT》和三页的《方案介绍》。材料内容用于理解设计背景，技术表述再与当前源码核对。原始附件未加入公开包，下面保留整理后的结论与实现入口。

## 可以保留的设计内容

- 演示第 1 页：有限 Golden SQL 样本和混合 Mock 数据下的路线选择，整理为[方案设计](solution.md)的背景。
- 演示第 2 页：单题运行与正确、错误资料维护之间的关系，整理为知识维护流程图。
- 方案第 1 页：数据特征不明确、业务口径缺失、重复错误结果三类问题，整理为问题与机制对照表。
- 方案第 2 至 3 页：逻辑指引、数据侦察、执行反馈与拦截流程，分别映射到具体代码，并增加自造数据演示。

## 表述差异与处理

| 历史材料中的写法 | 当前实现 | 文档处理 |
| --- | --- | --- |
| `common.knowledge.md` | `common_knowledge.md` | 使用当前文件名 |
| `logic_guide.json` | `logic_guides.json` | 使用复数文件名与配置路径 |
| `data_exe_result` | 默认结果名为 `dataset_exe_result.json`，位于 `output/<profile>/` | 补充可直接执行的命令和真实输出路径 |
| 独立 `sql_exe.py` 执行环节 | 当前入口使用 `execution_tools.py` 中的 `SqlExecutorTool` | 图中标明当前模块，避免指向缺失入口 |
| 独立 `manual_sql_test.py` 人工侦察脚本 | 不在公开仓库 | 保留探查思路，不列为可运行入口 |
| 注入 System Prompt | 当前图把组装的任务提示放入 `HumanMessage`，再附工具历史 | 使用“上下文注入”，不把它描述为实际 SystemMessage |
| 强制先侦察 | 当前通过 Prompt 要求，没有独立阶段校验节点 | 区分提示词协议与状态机强制约束 |
| 第 5 次后优化提示并持续拦截 | 第 5 次返回换思路提示，第 6 次仍失败时放行 | 写明精确分支，不描述为严格正确性保证 |
| 只有通过全部检查才保存 | 无历史时可能跳过黑名单，重试上限后也可能放行；最终会重执行 SQL | 说明检查覆盖范围与放行条件 |
| `temperature=0.0` 确保稳定 | 参数仍在，但模型版本、服务和工具轨迹可能变化 | 不声称完全确定性 |
| 高准确率、鲁棒性或并发带来明显提速 | 当前没有公开的全量评测、消融或吞吐量实验 | 只记录已完成的功能检查，不推算表现 |
| 官网提交与正确、错误反馈回流 | 当前没有官网自动提交或自动拉取评测程序 | 标注为外部判断和人工维护流程 |

这个对应关系也解释了为什么当前说明采用“单 Agent + 上下文与工具反馈”，而没有把方案写成多 Agent 协作、模型微调或向量检索系统。
